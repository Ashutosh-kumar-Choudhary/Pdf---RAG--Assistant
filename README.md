# PDF Question Answering (Local RAG)

Upload a PDF and ask questions about it. Answers are generated by a language model running **fully on your own machine**, using only the content of the document, and every answer shows the document name and page numbers it came from. No API keys and no cloud services.

## How it works

1. **Extract**: PyMuPDF reads the text of every page.
2. **Chunk**: each page is split into chunks of 100 words, tagged with document name and page number.
3. **Embed**: each chunk is converted into a 768-dimension vector with `nomic-embed-text` (via Ollama).
4. **Store**: vectors are saved in a persistent ChromaDB collection.
5. **Retrieve**: the question is embedded the same way, and the 3 most similar chunks are fetched.
6. **Generate**: the chunks and the question are sent to Qwen3 4B (via Ollama), which is told to answer only from the context, or say it could not find the answer.
7. **Cite**: the app lists the source document and page of each chunk used.

## Tech stack

Python, Streamlit, Ollama, Qwen3 4B, nomic-embed-text, ChromaDB, PyMuPDF

## Run it

1. Install [Ollama](https://ollama.com) and download the two models:

   ```bash
   ollama pull qwen3:4b
   ollama pull nomic-embed-text
   ```

2. Install the Python packages:

   ```bash
   pip install -r requirements.txt
   ```

3. Start the app:

   ```bash
   streamlit run app.py
   ```

4. Upload a PDF, wait for "PDF processed successfully!", then ask a question.

## Limitations and ideas for improvement

- Chunks do not overlap, so an answer that spans two chunks can be cut.
- Scanned PDFs (images) are not supported because there is no OCR.
- Each question is answered on its own, with no chat memory.
- Retrieval quality has not been formally evaluated.
- Planned: chunk overlap, per-document filtering, batched embedding, cosine distance, and a small evaluation set.
